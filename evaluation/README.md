# 常見問法題庫與調校

這是評估與流程調校，不會訓練或更新模型權重。`faq-cases.json` 有27個調整用案例與8個保留案例，涵蓋一般知識、即時查詢、缺資訊時追問、連續對話、重載記憶、待辦隔離及圖片搜尋。

參考字詞只供評分器使用，不送入 bot、Ollama prompt 或搜尋查詢。bot 只收到問題和合成的 LINE 事件；上網查到的來源仍會交給本機模型整理。題庫沒有被載入正式 bot 當成答案庫。這不能證明預訓練模型從未看過這些知識。

## 執行

在 repo 根目錄啟用既有虛擬環境，先執行調整用題目：

```sh
.venv/bin/python scripts/evaluate-faq.py --split development
```

完成通用修正並固定程式後，再跑保留案例：

```sh
.venv/bin/python scripts/evaluate-faq.py --split holdout
```

換成另一個已安裝模型時，沿用同一份題庫：

```sh
.venv/bin/python scripts/evaluate-faq.py --model 已安裝的模型名稱 --split development
```

每次產生新的 `test-evidence/faq-runs/*.json`，不覆蓋先前紀錄；也可用 `--output repo內新的檔案路徑` 指定目的地。紀錄包含模型、時間、程式及題庫雜湊、每題回答／來源／耗時與分類。執行期間改動核心程式會被標為 `code_unchanged=false`，不能當成同一固定版本的驗收。

這個流程使用暫存待辦與記憶、真實 BotRuntime 背景工作、本機 Ollama 及公開搜尋，回覆在本機截取。不讀正式 `.env`、不操作手機、不發送真實 LINE 回覆、不寫 Google，也不切換正式 Webhook。真實 LINE 顯示、LINE 圖片下載及 Google 寫入須另列實測，不能用這份紀錄冒充。

## 怎麼解讀

- `主答案字詞符合，需抽查`：符合參考字詞與來源存在檢查。不是完整語意判斷；每句補充、否定關係與來源是否支持主張仍需抽查。
- `符合預期`／`追問`：符合操作或追問檢查。
- `查不到`：沒有可靠來源；只有本來就預期拒絕的題目才算該檢查通過。一般知識查不到仍是缺漏。
- `待人工核對`：例如現任人物和今日新聞，僅確認來源條件，不自動當作答對。
- `未符合參考，需複核`、`來源不足`、`執行失敗`等保留為失敗，不刪除。

通過數混合不同功能檢查，不應稱為整體問答準確率。保留題的樣本很小，若看過結果後再針對它調整，就應轉成調整案例，另外準備新的保留題。不同時間或模型比較時，網頁和新聞也可能改變，不能把所有差異都歸因於模型。

## 換模型會不會重來

不用重建題庫或重新撰寫搜尋與對話流程，但新模型仍要重新評估；提示詞、結構化輸出及圖片能力可能需要調整。本工作沒有產生可移植的微調權重，也不把新增題庫或修改提示詞稱作模型訓練。

## 本輪結果與限制

- 27個調整案例初輪：22項符合檢查、4項未符合、1項待人工核對，保留於 `test-evidence/faq-development-baseline.json`。
- 通用調整後：25項符合、2項待人工核對，見 `faq-development-final.json`。
- 首次8個保留案例在固定版本下符合檢查，見 `faq-holdout-final.json`；這是小型保留集，不是未知世界問題的準確率。
- 隨後整合測試發現圖片「先問時間、再問日期」會漏掉原始辨識描述，已修正；失敗留在 `http-live-quality-faq-failure.json`，修後22項整合檢查通過。
- 最終同一版35例的完整回歸：33項符合檢查、2項待人工核對、0未執行，見 `faq-regression-final.json`。這次重跑包含已看過的保留題，因此標為回歸，不重新宣稱盲測。現任人物與今日新聞仍需人工核對。
- 77項 Python 回歸測試通過，含評分器不把參考答案送入事件、保留題區分、人工核對不自動當成答對，以及逾時／晚到回覆不串題。

一次較早的完整重跑出現來源缺漏與逾時，舊版測試器隨後因晚到回覆配對錯誤而退出，只有終端紀錄，沒有完整逐題JSON；已保留 `faq-regression-interrupted.txt`。新版改成每個事件獨立收件匣、每題寫入進度；逾時就停止並列出未執行數，不會把晚到回答當成下一題。連線健康檢查後才進行最後一次重跑；不能因此宣稱外部搜尋永遠穩定。

完整回歸指令：

```sh
.venv/bin/python scripts/evaluate-faq.py --split all
```

報告會標示 `complete`、`aborted_reason`、`completed`及`not_run`；退出碼0只表示自動檢查未失敗，仍可能有待人工核對。每題也會保存實際查到的來源摘要，方便人工檢查主張是否由來源支持。

正式服務曾出現公開通道連續檢查失敗、回復備援也未確認，達到三次重建上限後停止。這輪重新啟動時已先恢復自有路由的備援，再建立新通道；最後本機健康檢查、公開HTTPS及LINE endpoint讀回都通過，見 `test-evidence/faq-service-start-check.json`。這只是入口及啟動確認，不是真實手機訊息收發驗證。
