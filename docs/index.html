原本的問題

第一版的 LINE Bot 可以記錄待辦事項，但沒有提供查詢功能。使用者只能新增，無法回看自己過去記下的內容。

調整原先計畫的原因：讓「記錄」形成可回看的完整流程，增加工具的實用性。

修改內容

改善版新增「查詢」指令，只列出發訊者自己的待辦，最新在前，最多顯示 10 筆。沒有紀錄時，說明如何新增；缺少使用者身分或讀取失敗時，提供明確提示。

不支援的輸入也會同時說明「記錄」與「查詢」的使用方式。

額外驗證

  • 沒有待辦：提醒先新增，不產生紀錄。
  • 超過 10 筆：只顯示最新 10 筆，並列出總筆數。
  • 重新開啟檔案：紀錄仍可讀取，不混入其他 userId 或無身分舊資料。
  • Webhook：驗簽後記錄，再以同一 userId 查詢；回覆 API 以替代函式驗證。
  • 讀取失敗、身分缺失與不完整輸入：回覆清楚提示。

使用說明

在 LINE 個人聊天使用

  1. 輸入 記錄：星期五交報告，收到「已記錄：星期五交報告。」
  2. 輸入 查詢，查看自己的最新 10 筆待辦。
  3. 輸入 記錄： 時，Bot 會提醒補充事項。
  4. 輸入其他文字時，Bot 會提供記錄與查詢兩種使用方式。

不需要在 Bot 串接生成式 AI。AI 的角色是協助開發、測試與整理成果。

從本機到真人測試

需建立 LINE 官方帳號並啟用 Messaging API，在本機設定 Channel Secret、Channel Access Token，再啟動 Bot，取得能連入 /webhook 的 HTTPS endpoint。

在 LINE Developers 驗證 Webhook URL、啟用 Use webhook 並加好友後，親自測試正常、不完整與不支援輸入，保存截圖或影片。

這個 GitHub Pages 網頁只提供開發紀錄，不能執行 Bot。

查看完整設定步驟與已知限制 · LINE 官方設定說明

已知限制

目前以同步 JSONL 檔案保存，尚無刪除、完成狀態與定時提醒；不支援多執行個體。若 reply API 失敗，資料可能已保存，重試與回覆狀態追蹤仍待改善。請使用個人聊天，避免群組成員看見私人待辦。

AI 協作開發紀錄

  1. 需求整理：以第一版為起點，確認「只有記錄，不能回看」的問題，將查詢列為本次改善。
  2. 程式修改：Codex 新增 userId 篩選、最新排序、十筆上限與錯誤提示，保持原本記錄功能。
  3. 重新測試：執行 14 組本機測試；另實際執行第一版封存程式與改善版，產生前後回覆比較。
